# Content

content-heading: New artefacts for a new kind of product

content-body: When the system acts autonomously on behalf of the user, classic discovery artefacts are not enough. We need a new set of questions, new personas, and new outputs — before design or development starts.



bullet-1-title: A second persona — the agent

bullet-1-body: Traditional personas capture user goals and frustrations. Agentic discovery adds a second layer: what context, data, and permissions does the agent need to serve that user? Human users and agent actors — both need a persona.



bullet-2-title: Journey maps with an agent lane

bullet-2-body: The standard journey map shows what the user does and feels. Add a second lane: what the agent does autonomously, what it escalates to the human, and where it could fail silently.



bullet-3-title: The delegation question

bullet-3-body: Discovery must answer: at what point does the user need to be back in control? That is not an edge case to resolve in QA — it is a primary design requirement that shapes the entire system.



bullet-4-title: HITL map as a discovery output

bullet-4-body: Before design starts, discovery should deliver a first-draft HITL map — which agent actions are auto / approve / audit. This is a research output, not only an engineering one. It belongs in the discovery phase.



bullet-5-title: Clients lose less between discovery and build

bullet-5-body: When a prototype takes shape in the room and a structured backlog comes out of the session, discovery becomes one continuous motion with development — not a phase that precedes it. Shorter cycles, less waste in handoff, fewer surprises when build begins.
